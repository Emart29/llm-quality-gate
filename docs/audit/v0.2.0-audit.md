# Audit of v0.2.0, and what carries into 1.0

Version 0.2.0 is tagged `v0.2.0` and published as `llmq-gate` 0.2.0 on PyPI. Version
1.0 is measured against it, so this note records what 0.2.0 actually does, with
evidence, before anything changes.

## Baseline facts

- **The tag matches PyPI.** All 41 Python files in the PyPI source distribution are
  byte-identical to the `v0.2.0` tag.
- **The test suite no longer fully passes.** The README says 111 tests pass. With every
  declared dependency installed (Windows, Python 3.11), 108 pass and 3 fail:
  - Two tests in `tests/test_production_readiness.py` read `route.path` from every route,
    and newer FastAPI versions (0.137) add router objects that have no `.path`.
    Dependencies are unpinned, so the suite drifted without any code change.
  - `test_consistency_metric_lightweight_mode` clears *every* environment variable and then
    loads the real embedding model, which needs a home directory to find its cache. Its
    comment assumes `sentence-transformers` is absent, although it is a declared
    dependency. Without that package, 109 pass.
- **Exact versions** used for this audit are in `v0.2.0-environment.txt` in this folder, so
  the baseline can be reproduced later.
- **The bundled dataset** has 21 cases across 10 task types. Most task types have 1–3
  cases. The README's example run shows 12.

## Findings

Each finding was reproduced directly against the 0.2.0 code, not inferred from reading it.

### 1. A provider error is recorded as a successful empty answer

Providers return errors in the response object instead of raising them. The runner
retries only on exceptions and never checks `response.error`. A simulated HTTP 429 from
the provider produced:

```
success: True | output: '' | error: None | provider calls: 1
```

A rate limit is therefore scored as a real (empty) model answer, with no retry and no
recorded error. A run that hits a quota wall reports bad quality instead of an
incomplete run.

### 2. In CI, the "semantic" scores are partly random

When `CI=true`, as it is on GitHub Actions, embeddings come from `MockEmbeddingModel`.
That model is built on Python's `hash()`, which is randomised per process. The
docstring says the results are deterministic, but they are not. The same input, scored in
four separate processes:

| Run | task_success | relevance |
|---|---|---|
| 1 | 0.8037 | 0.9981 |
| 2 | 0.9025 | 0.9978 |
| 3 | 0.6811 | 0.6802 |
| 4 | 0.8521 | 0.6698 |

The default thresholds are 0.8 and 0.7, so the same answer passes or fails depending on
the run.

### 3. The hallucination verdict is a substring match

The verdict is `"HALLUCINATED" in response.upper()`. A judge reply of
`VERDICT: GROUNDED` followed by "No hallucinated facts." is scored as a hallucination.
The judge has never been validated against human labels.

### 4. The task-success judge parser defaults silently

| Judge reply | Score recorded |
|---|---|
| `Score: 0.9` (lowercase) | **0.5** (silent default when the regex misses) |
| `SCORE: 9/10` | **1.0** (reads "9", then clamps it) |

Any exception in the judge path falls back silently to embedding similarity. A single run
can therefore mix judge scores and similarity scores without saying so.

### 5. The metrics do not measure what their names say

- **Relevance** is the cosine similarity between the *prompt* and the answer, which
  measures topical overlap, not relevance.
- **The hallucination fallback** is `1 − similarity(answer, reference)`, so a correct
  answer in different words scores as a hallucination.
- **Consistency** is skipped at temperature 0 on the assumption that outputs are
  identical, which is not true of every provider. With fewer than two outputs it scores
  1.0. In CI it is computed from the variance of output *lengths*.
- **Skipped metrics** contribute a score of 1.0 to the batch average.

### 6. Regression detection is unpaired and has no noise estimate

`_compare_against_baseline` compares one run's averaged scores with one stored baseline,
using a fixed tolerance of 0.03 on five metrics at once. It has no repeated runs, no
per-item pairing and no interval. With 21 cases, one changed item moves a binary metric by
about 0.048, more than the tolerance. Combined with finding 2, noise alone can trigger a
"regression".

### 7. Retry logic exists but is not used on the evaluation path

`BaseLLM.generate_with_retry` in `llm/base.py` retries every error, including 400s, with
fixed exponential backoff and no regard for `Retry-After`. Nothing on the evaluation path
calls it.

### 8. Packaging collides with other projects

The wheel installs top-level packages named `cli`, `core`, `llm`, `evals`, `storage` and
`dashboard`. Any other installed package using one of those names collides with it.
`requires-python` is `>=3.8`, which is past end of life, and the author field is a
placeholder.

### Checked and found sound

- **The judge does run.** It calls `generate(messages=...)` while providers define
  `generate(request)`, but the `BaseLLM` adapter in `llm/factory.py` translates between
  them. The judge path is not dead.
- **The PyPI release matches the tag** (above).

## Keep, rewrite or delete

| Path | Decision | Reason |
|---|---|---|
| `core/` (config, errors) | **Keep** | Small and sound |
| `llm/` providers | **Rewrite** | Errors must be raised and typed. Retry only on 429/5xx/timeout, honouring `Retry-After`; never on other 4xx. Record usage and cost. Keep Groq, Gemini, OpenRouter, Ollama and a generic OpenAI-compatible client. Remove HuggingFace, LocalAI and Claude from 1.0. |
| `llm/factory.py` `BaseLLM` adapter | **Keep the idea** | Replaced by a single request type, so no adapter is needed |
| `evals/metrics.py` | **Rewrite** | Task-specific scorers (exact match, F1, correct refusal). One judge with structured output, validated against hand labels. Remove `MockEmbeddingModel`, prompt-to-answer "relevance", and the similarity-based hallucination fallback. Consistency becomes the measured noise floor. |
| `evals/runner.py` | **Rewrite** | Check provider errors; K repeated runs; frozen item IDs for pairing |
| `evals/service.py` regression logic | **Rewrite** | Paired comparison with an interval and a block / pass / inconclusive verdict |
| `evals/dataset.py` | **Keep, extend** | The model shape is fine; add suite, frozen item ID and licence |
| `evals/dataset.json` | **Delete from 1.0** | Kept at the `v0.2.0` tag as the baseline. Replaced by frozen suites. |
| `evals/validator.py`, `maintenance.py`, `comprehensive_runner.py` | **Delete** | Superseded by the new runner and suites |
| `storage/` (DuckDB) | **Keep, new schema** | File-based storage suits CI with no server. The gateway's cost ledger goes in PostgreSQL. |
| `cli/` (Typer) | **Keep the shape, rewrite commands** | `llmq init` and `llmq eval` stay familiar to 0.2 users |
| `ci/` | **Rewrite** | Post the verdict, effect size and interval as a PR comment; fail on "block" |
| `.github/workflows/` | **Rewrite** | Clean-environment install, Python 3.10–3.12 matrix, the gate job |
| `dashboard/` | **Delete** | Replaced by Grafana (gateway metrics) and a static report |
| `website/` (Next.js) | **Delete** | Replaced by the static report on GitHub Pages |
| `docs/` presentation and demo assets | **Delete** | Rewritten for 1.0 |
| `demo_ci_performance.py` | **Delete** | Tied to the mock-embedding CI mode |
| `Dockerfile` | **Rewrite later** | For the gateway image |
| `tests/` | **Keep what covers kept code; rewrite the rest** | |
| Packaging | **Rewrite** | One `llmq` package namespace; pinned dependency ranges; Python ≥ 3.10; heavy embedding dependencies move to an optional extra |

## Reproducing the baseline

```
pip install -c docs/audit/v0.2.0-environment.txt llmq-gate==0.2.0
```

Or check out the `v0.2.0` tag. The comparison in 1.0 runs this version on its own
bundled 21-case dataset and on the new frozen suites.
